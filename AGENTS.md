# glances-cubeui

CubeUI Glances: a cubeui dashboard for one or more [Glances](https://github.com/nicolargo/glances) servers (`glances -w`).
A Node server samples each host's `/api/4/all`, keeps a short in-memory history and serves it over
GraphQL (queries plus an SSE subscription); a React app built from the cubeui registry draws it.

## Run

```
cp .env.example .env    # set GLANCES_HOSTS=name=http://host:61208[,name2=...]
npm install
npm run dev             # web on http://localhost:3000, API on :8787
npm run check && npm test
npm run build && npm start   # one process on PORT (default 3000) serving dist/
docker compose up -d --build # the same, in a container; reads GLANCES_HOSTS and PORT from .env
```

`SAMPLE_INTERVAL_SECONDS` (default 3, from 0.5 to 300) sets how often every host is sampled; `.env.example` documents it with `PORT` and `TRUST_PROXY`.

## Layout

- `server/core/` config getters, `defaults.ts` groups, coded errors, preflight
- `server/glances/` one Glances server: host list parser, HTTP client, zod parsing into a `Reading`; `filesystem-view.ts` and `traffic-view.ts` narrow a reading to a detail level
- `server/monitor/` the sampler loop, the per-host store and history, the bus subscriptions follow
- `server/graphql/` SDL, schema, operation limits, logger; `write-schema.ts` prints `schema.graphql`
- `server/http/` `createApp(deps)`, health, shutdown; `server/index.ts` only boots
- `web/src/components/` vendored cubeui and shadcn code: do not edit, reinstall with `npx shadcn@latest add @cubeui/<item>`
- `web/src/core/` typed GraphQL helper, query client, formatters, extra icons
- `web/src/hosts/` host hooks, card and status badge; `web/src/readings/` rings, charts and tables; the overview and the host page draw the same `ReadingRings` and `UsageChart`
- `web/src/settings/` per-browser settings: `defaults.ts` (the `Settings` type and its defaults), the localStorage store, `useSettings()`
- `web/src/routes/` TanStack file routes (`/`, `/hosts/$hostName`, `/settings`); the tree is generated by `npm run codegen`
- `tests/` mirrors `server/` (and the pure parts of `web/src/`); `tests/fixtures/glances-all.json` is an anonymised Glances payload

Settings (update interval, units, detail level, OS storage, process count, density) live in the browser's localStorage, one set per browser. The update
interval is honoured by the server: `hostChanged(intervalSeconds:)` thins the stream per subscriber (`server/monitor/paced-watch.ts`).
The detail level is too: `Reading.filesystems`, `networkInterfaces` and `disks` take `detail: SUMMARY | USEFUL | ALL`, and the
server totals pools and leaves out what a level hides. Charts and the overview always sum the physical interfaces.

The dense view is one rule in `web/src/index.css`: `useDensity()` puts `data-density` on the root element and the rule shrinks
Tailwind's `--spacing`, so anything that must keep its size in that view is sized in rem (the rings are).

The server stores nothing and nobody signs in: keep it on a trusted network.
